# 07 前端可视化

2026 年，工作流可视化已不是"锦上添花"而是生产级系统的必备能力（LangGraph 等框架把"状态驱动、可视化、可中断"列为核心特性）。Ariadne 提供三种互补视图，分别对应设计时、观测时、循环时。

## 1. 视图一：DAG 工作流拓扑图

### 1.1 设计时（编排）

拖拽式节点编排，节点类型与配置：

| 节点类型 | 配置项 | 输出 |
|---|---|---|
| **LLM 调用** | provider、model、prompt 模板、参数、结构化输出 schema | text / structured |
| **工具调用** | 工具名、参数映射、超时、重试策略 | tool result |
| **RAG 检索** | 检索器、top_k、过滤条件、重排 | documents |
| **代码执行** | 语言、沙箱 profile、超时 | stdout / artifact |
| **条件分支** | CEL 条件表达式 | 多出边 |
| **Loop 子图** | Goal 定义（断言 + 预算 + 模式） | 收敛结果 |
| **评估节点** | 评估器列表、阈值 | 分数 + 断言结果 |

**Loop 作为可嵌套的子图节点**，这是与纯 DAG 编排器的关键区别：DAG 本身无环，但 Loop 节点内部是受控循环，外部看仍是一个单入单出的节点。这样既保持拓扑可静态分析，又表达了迭代语义。

编排产物直接序列化为 `spec.yaml`（见 [04 Harness](04-harness-and-sandbox.md#5-spec-驱动)），保证 UI 编排与代码定义是同一份事实源，可双向转换。

设计时校验（保存即校验，不等运行）：环检测（Loop 节点外不允许成环）、类型兼容（上游输出类型与下游输入契约匹配）、必填参数缺失、断言可验证性。

### 1.2 运行时（状态）

同一张图叠加实时状态：

| 状态 | 视觉表现 |
|---|---|
| `pending` | 灰色描边 |
| `running` | 蓝色 + 呼吸动画 + 已耗时计数 |
| `success` | 绿色实心 |
| `failed` | 红色 + 错误图标 |
| `blocked` | 橙色 + 盾牌图标（Harness 拦截） |
| `skipped` | 虚线描边 |
| `awaiting_approval` | 紫色 + 人形图标 |

节点上直接显示耗时、Token、成本三个数字；边上显示流转的数据量摘要。**关键路径高亮**：自动计算并加粗耗时最长的路径，一眼看出瓶颈。

点击节点展开抽屉，显示完整 Span 数据：输入输出全文（大 payload 走预签名 URL 懒加载）、Token 明细（含缓存命中）、模型实际响应版本、Harness 求值记录、重试历史。

## 2. 视图二：Trace 调用树

一次完整请求渲染为嵌套调用树：

```
用户请求 (Trace 4bf92f...)                          总计 2.4s · 2,090 tok · $0.021
├── Harness 约束检查                                  2ms   ✅ 5 规则通过
├── LLM 调用 #1 · gpt-4o-2024-11-20                 1.2s   1,234 tok  $0.012
│   ├── 输入   System Prompt + User Query           (展开)
│   └── 输出   思考过程 + 工具调用请求               (展开)
├── 工具调用 · 数据库查询                            340ms  ⚠ 慢查询
│   ├── 输入   SELECT * FROM orders WHERE ...
│   └── 输出   47 条记录 (12.4 KB)
├── LLM 调用 #2 · gpt-4o-2024-11-20                 0.8s     856 tok  $0.008
│   └── 输出   最终回答                              (展开)
└── 评测引擎                                          45ms
    └── 事实性 92 · 指令遵循 100 · 相似度 87  → 复合 93 ✅
```

功能要点：

- **颜色编码**：绿=成功，黄=有警告（慢/降级/重试），红=失败，橙=Harness 拦截。
- **筛选与搜索**：按耗时、Token、成本、状态、模型名、规则 id 过滤；全文搜索 prompt/completion 内容。
- **时间轴（甘特）视图**：横向展示各 span 的时序与重叠关系，区分"串行慢"与"并发等待"。
- **自动瓶颈标注**：耗时占比 > 30% 的 span 加标记；成本占比 > 40% 的加标记。
- **异常聚类**：同一 trace 内重复出现的相同错误折叠为"× N"。

对比模式：并排两条 trace，逐 span 对齐 diff，用于回答"为什么这次比上次慢/贵/差"。

## 3. 视图三：Loop 迭代进化视图

这是 Loop Engineering 的专属视图，也是 Ariadne 最具差异化的界面。

```
目标：复合质量 ≥ 85 · 引用 ≥ 3 · Markdown 格式    预算 $0.10 / 8 轮
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

轮次 1   得分 62   1,234 tok   $0.012   2.3s   ❌
  失败    事实性不足（78 < 85）· 引用缺失（0 < 3）
  证据    "第2段的性能数据无来源"
  指令    补充至少 3 个引用来源，为性能数据标注出处

轮次 2   得分 78   1,567 tok   $0.015   2.8s   ❌   ↑16
  失败    Markdown 格式不符（缺少一级标题）
  证据    首行为 "本文介绍..."，未以 # 开头
  指令    以一级标题开头，代码块标注语言
  已排除  ✗ 纯文本罗列引用（轮次1 试过，未通过格式校验）

轮次 3   得分 94   1,023 tok   $0.010   1.9s   ✅ 达标   ↑16
  通过    全部 3 项断言
  模型自称完成: 是 · 外部裁决: 达标 ✅

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
合计  3 轮 · 3,824 tok · $0.037（预算 37%）· 7.0s
```

四个组成部分：

1. **得分趋势折线图**：多维度分数叠加（复合分 + 各子维度），横轴轮次；阈值画横线，一眼看出何时越线。Judge 版本切换处画竖线标注。
2. **Token / 成本柱状图**：每轮成本对比，堆叠区分输入/输出/缓存命中；累计成本折线叠加预算上限。
3. **轮次间 Diff**：自动高亮"这一轮比上一轮改了什么"。内容类用文本 diff，代码类用语法感知 diff。
4. **失败签名时间线**：横向展示每轮的 `failure_fp`，相同签名连续出现时高亮 —— 这是振荡的直观呈现。

诊断提示（前端根据终态给出可操作建议）：

| 终态 | 提示 |
|---|---|
| `STALLED` | 反馈信号无效。失败签名恒定在 `metric` 类断言 → 建议补充 `hint` 或改用 `command` 类断言 |
| `BUDGET_EXCEEDED` | 预算不足。前 N 轮得分趋势为上升 → 建议提高预算；趋势平坦 → 先修断言设计 |
| `MAX_ITERATIONS` | 轮次耗尽但仍在改善 → 提高 `max_iterations` |
| `BLOCKED` | Harness 硬拦截，展示命中规则与表达式，不建议重试 |

**策略对比模式**：并排展示同一目标在不同 Loop 模式 / 模型 / 温度下的进化轨迹，对比达标轮次与总成本，用于选出最经济的配置。

## 4. 技术实现

| 组件 | 技术 | 说明 |
|---|---|---|
| DAG 渲染 | React Flow | 节点拖拽、连线、自定义节点、状态动画；内置 minimap 与自动布局（dagre） |
| Trace 树 | 自研嵌套组件 + TanStack Virtual | 现成库不满足"折叠 + 多维筛选 + 关键路径高亮"组合需求 |
| 时间轴 / 趋势 / 柱状 | ECharts | 大数据量渲染性能优于手写 D3；支持 canvas 渲染模式 |
| Diff | 自研（文本用 diff-match-patch，代码用 Shiki + 行级对齐） | |
| 服务端状态 | TanStack Query | 缓存、失效、乐观更新 |
| 实时通道 | SSE | 见下节 |

### 4.1 SSE 实时协议

选 SSE 而非 WebSocket：数据流是**单向服务端推送**，SSE 自带断线重连与 `Last-Event-ID` 续传，基于 HTTP 无需额外协议栈与代理配置。

```
GET /v1/loops/{loop_id}/stream
Accept: text/event-stream
Last-Event-ID: 42          # 断线重连时续传

event: state
id: 43
data: {"iteration":2,"state":"EXECUTING","elapsed_ms":1240}

event: node
id: 44
data: {"node_id":"llm-1","status":"success","tokens":1567,"cost_usd":0.015}

event: verdict
id: 45
data: {"iteration":2,"converged":false,"score":78,"failed":["markdown-format"]}

event: critique
id: 46
data: {"failures":["缺少一级标题"],"directives":["以一级标题开头"]}

event: terminal
id: 47
data: {"final_state":"CONVERGED","iterations":3,"total_cost_usd":0.037}
```

服务端实现要点：事件从 Redis pub/sub 广播（多 API 实例都能推）；每个连接维护 `Last-Event-ID` 游标，重连时从 Postgres 补齐缺失事件；心跳注释帧每 15s 一次防代理超时；单连接推送速率限制（高频节点更新在服务端合并为 100ms 一批）。

### 4.2 大数据量优化

| 问题 | 方案 |
|---|---|
| 单 trace 上千 span | 虚拟滚动 + 默认折叠深度 2 层 + 按需懒加载子树 |
| Span 列表万级 | 服务端分页 + 游标（不用 offset，深分页会退化） |
| 大 payload（MB 级） | 预签名 URL 直读 S3 + 前 512 字节预览 + 点击才拉全文 |
| 长 Loop（数十轮） | 趋势图降采样；轮次卡片虚拟化；默认只展开最近 3 轮 + 失败轮 |
| DAG 节点上百 | 自动分组折叠（按子图）+ minimap 导航 |
| 实时更新抖动 | 服务端 100ms 批合并 + 前端 requestAnimationFrame 节流 |

## 5. Playground

用于交互式调试单个环节，与 Loop 打通：

- 编辑 prompt / 参数 / 模型，即时执行看结果。
- 同一输入并排跑多个配置（模型 × 温度 × prompt 版本），对比输出与成本。
- 一键"把这个配置固化为 spec"或"以这个输入创建 Loop"。
- 从任意历史 span 一键"在 Playground 中打开"，用原始输入复现问题。

## 6. 无障碍与国际化

- 所有交互元素支持键盘操作，Trace 树支持方向键导航与 `Enter` 展开。
- 状态**不只靠颜色**表达，同时用图标与文字（色盲可用）。
- 图表提供数据表格视图作为等价替代，屏幕阅读器可读。
- 焦点可见、ARIA 标签完整、对比度满足 WCAG AA。
- 界面文案外置为资源文件，首版提供中英文；日期/数字/货币按 locale 格式化。

## 7. 响应式设计与主题系统

### 7.1 移动端适配

三断点响应式布局：

| 断点 | 宽度 | 布局策略 |
|---|---|---|
| 移动端 | < 768px | 侧边栏收起为汉堡菜单；卡片堆叠为单列；表格横向滚动或折叠为卡片；DAG 图支持双指缩放 |
| 平板 | 768px - 1024px | 侧边栏可收起；卡片 2 列网格；表格保持完整 |
| 桌面 | > 1024px | 侧边栏常驻；卡片 3-4 列网格；多面板并排显示 |

**触控优化**：
- 所有可点击元素最小 44×44px 触控目标（WCAG 2.1 Level AAA）
- 抽屉/模态框支持下滑关闭手势
- 长列表支持下拉刷新
- DAG 图支持触控拖拽节点与双指缩放画布

### 7.2 暗色模式

**设计哲学**：Newsprint 印刷报纸风格 —— 日间是纸底墨字，夜间反转为墨底纸字。

**实现方式**：
- 单份设计令牌，使用 CSS `light-dark()` 函数自动切换
- 主题状态存储在 `localStorage`，默认跟随系统偏好（`prefers-color-scheme`）
- 用户可手动切换，覆盖系统设置
- 切换时无闪烁：通过内联脚本在首屏渲染前注入 `data-theme` 属性

**色彩对比度**：
| 元素 | 日间模式 | 夜间模式 | 对比度 |
|---|---|---|---|
| 正文 | #111 on #f7f7f4 | #f2f2ed on #141412 | 14.1:1 |
| 次要文本 | #555 on #f7f7f4 | #aaa on #141412 | 7.5:1 |
| 社论红 | #cc0000 | #ff6b5e（自动提亮） | > 4.5:1 |
| 代码块 | #0f131c on #eee | #f2f2ed on #1e1e1c | > 7:1 |

**特殊处理**：
- ECharts 图表主题随模式切换重建（主题在 `init` 时固化，需重新实例化）
- 纸纹背景（data URI 的 SVG）在深浅模式下自动切换颜色
- 截图和导出功能保留当前主题状态

**动效降级**：
- 检测 `prefers-reduced-motion: reduce`，自动禁用非必要动画
- 保留状态变更等关键反馈动效，缩短持续时间

### 7.3 字体系统

三层字体栈保证跨平台一致性：

| 用途 | 字体栈 | 说明 |
|---|---|---|
| 正文/界面 | Noto Sans SC Variable (800), Inter Variable, system-ui | 醒目粗体中文 + 高可读性拉丁字符 |
| 代码/数据 | JetBrains Mono Variable, monospace | 等宽数字，清晰区分 0/O 和 1/l |
| 标题 | 继承正文，通过 `font-weight: 800` 加粗 | 统一视觉风格 |

**可变字体优势**：
- Noto Sans SC Variable：单个字体文件包含多字重（100-900），减少请求数
- 字重平滑过渡，避免合成粗体导致的模糊
- 所有字体通过 `@fontsource` 自托管，离线可用

**圆角设计**：
- 卡片/面板：14px（`--radius-lg`）
- 按钮：8px（`--radius-sm`）
- 输入框：10px（`--radius`）
- 标签/胶囊：999px（`--radius-full`）
- 全站统一令牌，无硬编码值

完整的 WCAG 合规需要辅助技术实测与专业无障碍评审，代码层面只能保证基础可访问性。
